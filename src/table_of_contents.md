## [01장. 궂이 왜? 혹은, 반론에 대한 답변](./ch01/ch01.md)

목표: Lisp에 대한 가장 흔한 반론들과 답변 + 최신 구현체 소개 및 본서에서 다룰 내용 미리보기

- 전에 Lisp를 봤는데 이해가 안 갔어요.
- 괄호 속 프로그램 구조가 보이지 않아요(작업 방식이 명확하지 않음).
- 제가 좋아하는 언어보다 훨씬 느려요.
- 다른 사람들은 Lisp로 개발하지 않아요 (사용률 낮음).
- GUI를 사용할 수 없어요.
- 외부 코드 호출이 불가능해요(타 시스템 통합 어려움).
- 실행 중 예측 불가한 지연 발생 (GC 관련).
- 언어 규모가 너무 커서 복잡해요.
- 인공지능 연구용으로만 사용된다고 알려져 있어요.
- 효율적인 개발 도구가 부족해요.
- 메모리 사용량이 과도해요.
- 디스크 공간을 많이 차지해요.
- 좋은 Lisp컴파일러를 찾을 수 없어요.

## [03장. 12개의 레슨으로 배우는 필수 리스프](./ch03/ch03.md)

목표: Lisp을 가장 간단한 형태로 설명(초보자를 혼란스럽게 할 수 있는 특수한 경우를 고려하지 않고)

- [레슨 01. 필수 - 신택스](./ch03/lesson_01.md)
  - 리스트는 괄호로 둘러싸여 있다.
  - 아톰(atom)은 공백이나 괄호로 구분된다.
- [레슨 02. 필수 - 평가](./ch03/lesson_02.md)
  - 폼(form)은 평가될 수 있다.
  - 함수는 인자를 적용할 수 있다.
  - 함수는 여러 개의 값을 반환할 수 있다.
  - 함수는 일반적으로 인자를 수정하지 않는다.
  - 함수 적용 전에 인자가 먼저 평가된다.
  - 인자는 왼쪽에서 오른쪽 순서로 평가된다.
  - 스페셜 폼(special forms)과 매크로(macros)는 인자의 평가 방식을 바꾼다.
- [레슨 03. 스페셜 폼과 매크로에 대한 예제](./ch03/lesson_03.md)
  - SETQ
  - LET
  - COND
  - QUOTE
- [레슨 04. 조립과 분해](./ch03/lesson_04.md)
  - CONS
  - LIST
  - FIRST 와 REST
- [레슨 05. 네이밍과 아이덴티티](./ch03/lesson_05.md)
  - 심볼(symbol)은 단순히 이름일 뿐이다.
  - 심볼은 항상 고유하다.
  - 심볼은 값을 가리킬 수 있다.
  - 하나의 값에는 여러 심볼이 연결될 수 있다.
- [레슨 06. 바인딩 vs 할당](./ch03/lesson_06.md)
  - 바인딩(binding)은 값을 저장할 새로운 공간을 만든다.
  - 바인딩은 이름을 지닌다.
  - 동일한 시점에 한 바인딩이 서로 다른 값을 가질 수 있다.
  - 가장 안쪽의 바인딩을 우선시 한다.
  - 프로그램은 오직 자신이 생성한 바인딩에만 접근할 수 있다.
  - 할당(assignment)은 기존 공간에 새로운 값을 부여한다.
- [레슨 07. 필수 - 함수 정의](./ch03/lesson_07.md)
  - DEFUN 이름이 있는 함수를 정의한다.
  - LAMBDA 이름이 없는(익명) 함수를 정의한다.
- [레슨 08. 필수 - 매크로 정의](./ch03/lesson_08.md)
  - DEFMACRO 매크로를 정의한다.
  - 매크로는 값이 아닌 폼(form)을 반환한다.
- [레슨 09. 필수 - 다중 값](./ch03/lesson_09.md)
  - 대부분의 표현식은 하나의 값만 생성한다.
  - VALUES 표현식은 여러 개(또는 없음)의 값을 생성한다.
  - 몇몇 특수 표현식은 여러 개의 값을 받는다.
  - 일부 표현식은 여러 개의 값을 전달한다.
- [레슨 10. 프리뷰 - 다른 데이터 타입](./ch03/lesson_10.md)
  - 리스는 숫자에 대해 거의 항상 올바른 동작을 수행한다.
  - 문자(characters)는 리스프가 읽고 쓸 수 있는 데이터를 제공한다.
  - 배열(arrays)은 데이터를 표로 정리한다.
  - 벡터(vectors)는 1차원 배열입니다.
  - 문자열(strings)은 문자만 포함하는 벡터입니다.
  - 심볼(symbol)은 고유하지만, 여러 값을 가질 수 있습니다.
  - 구조체(structures)는 관련 있는 데이터를 저장할 수 있게 해줍니다.
  - 타입 정보는 런타임에 확인 가능한다.
  - 해시 테이블(hash tables)은 키를 통해 빠르게 데이터에 접근할 수 있게 한다.
  - 패키지(packages)는 이름 충돌을 방지한다.
- [레슨 11. 필수 - 입력과 출력](./ch03/lesson_11.md)
  - READ는 Lisp 데이터를 읽어온다.
  - PRINT는 당신과 READ를 위해 Lisp 데이터를 출력한다.
  - OPEN과 CLOSE는 파일을 다룰 수 있게 해준다.
  - PRINT 관련 변종들.
- [레슨 12. 필수 - 리더 매크로](./ch03/lesson_12.md)
  - 리더(reader)는 문자를 데이터로 변환한다.
  - 표준 리더 매크로는 내장 데이터 타입을 처리한다.
  - 사용자 프로그램은 리더 매크로를 정의할 수 있다.

## [08장. 수명(Lifetime)과 가시성(Visibility)](./ch08/ch08.md)

목표: Lisp 변수의 값이 실행 중 수명과 가시성에 의해 어떻게 영향을 받는지를 보여준다. 다른 언어의 로컬/전역 변수와  매우 유사하지만, Lisp의 스페셜 변수(special variables)가 뭔가 변화시킨다. 이 장은 또한 변수에만 수명과 가시성이 있는게 아님을 이해하는 데 필요한 기초를 다진다.

- Lisp의 모든 것은 수명과 가시성을 가진다
- 수명(Lifetime): 생성, 존재, 그리고 파괴
- 가시성(Visibility): 볼 수 있고 보일 수 있는 것
- 기술적인 명칭: 범위(Extent)와 스코프(Scope)
- 매우 간단한 경우: 최상위 수준 폼 정의(top-level defining forms)
- 매개변수와 LET 변수의 스코프와 범위
- 약간 더 까다로운 경우: 스페셜 변수

- 단순한 할당은 디스트럭티브 모디피케이션이다
- 할당의 위험성
- 변경 vs. 복사: 효율성의 문제

- RPLACA, RPLACD, SETF ...; 순환성(circularity)

## [12장. 반복 대신 매핑](./ch12/ch12.md)

목표: 매핑 함수들을 분류하고 시연. 적절한 사용과 부적절한 사용을 보여줍. 시퀀스(sequence)의 개념을 소개.

- MAPCAR, MAPC, MAPCAN은 연속된 리스트 요소들을 처리한다
- MAPLIST, MAPL, MAPCON은 연속된 서브리스트(sublists)를 처리한다
- MAP과 MAP-INTO는 리스트뿐 아니라 시퀀스에 작동한다
- 매핑 함수는 필터링에 좋다
- 효율성을 중시한다면 매핑을 피하는 것이 더 낫다
- 술어(predicate) 매핑 함수는 시퀀스를 테스트한다
- SOME, EVERY, NOTANY, NOTEVERY

## [14장. 오브젝트가 정말 스스로 행동할 수 있는가?](./ch14/ch14.md)

- 일반 함수는 오브젝트에 행동을 부여한다
- 멀티 메서드(multimethods)에서는 메서드와 오브젝트 사이의 경계가 흐려진다
- 오브젝트가 아닌 것에 대한 메서드? 그렇다면 메서드는 어디에 존재하는가?
- 일반 함수는 인수의 스페셜라이져(specializers)를 기반으로 디스패치하여 작동한다

- 메서드 조합은 추가적인 선택지를 제공한다
- 어떤 것도 돌에 새겨지지 않았다; 메타 오브젝트 프로토콜 맛보기(peek)
